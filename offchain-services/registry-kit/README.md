# کیت رجیستری ایمیج سور (`registry.surnet.org`)

> **وضعیت (۲۰۲۶-۱۱-۲۵):** ✅ نرم‌افزار تصمیم‌شده: `registry:2` با nginx. ✅ کیت روی میزبان آزمون (`darya`، `192.168.1.210`) بالا آمد و ۱۱ آزمون دودی گذشت؛ ✅ به دستور مالک همان روز نمونه جمع شد (کانتینرها، حجم، پوشه و ایمیج `registry:2` پاک شد؛ ایمیج `nginx:alpine` ماند چون کانتینرهای دیگر میزبان از آن استفاده می‌کنند). 🔶 **سرور نهایی با IP عمومی، DNS و گواهی هنوز نیست** (کار باز ۱۸ در `sur-validator-monitoring-spec.md`؛ `sur-subdomain-plan.md` بخش ۵).
>
> الان هیچ رجیستری‌ای بالا نیست. کیت برای نصب روی سرور نهایی همین است، با همان دستورهای بخش «نصب».

## چه می‌کند

ایمیج‌های ولیدیتورها (ایجنت SurWatch، NodeCheck و در آینده Besu) روی سرور داخل ایران نگه داشته می‌شود تا ولیدیتورها بدون Docker Hub و GHCR بکشند.

## دو در (و چرا)

| در | پورت | دسترسی | کاربرد |
|---|---|---|---|
| خواندن | `5000` | بدون ورود؛ فقط `GET` و `HEAD` (نوشتن و حذف با ۴۰۳ رد می‌شود) | ولیدیتور `docker pull`؛ این در است که عمومی می‌شود |
| نوشتن | `5001` | همهٔ درخواست‌ها با ورود (htpasswd) | CI و مدیر؛ **هرگز عمومی نشود** (فقط روی شبکهٔ داخلی، VPN یا تونل ssh) |

دلیل دو در: اگر `/v2/` بدون ورود ۲۰۰ بدهد، کلاینت داکر هنگام push رمز نمی‌فرستد؛ پس «خواندن عمومی و نوشتن با ورود» روی یک در کار نمی‌کند.

## فایل‌ها

| فایل | کاربرد |
|---|---|
| `docker-compose.yml` | `registry:2` (با digest پین‌شده) و `nginx:alpine`؛ محدودیت حافظه و CPU؛ حجم `sur-registry-data` |
| `nginx.conf` | دو سرور بالا |
| `smoke-test.sh` | ۱۱ آزمون: خواندن، نوشتن، رد شدن نوشتن روی در عمومی، `login`، `push`، `pull`، برابری هش؛ با `WIPE=1` حجم آزمایشی را پاک می‌کند |

دو فایل **در مخزن نیستند** و روی سرور ساخته می‌شوند: `htpasswd` (کاربر `ci`، هش apr1) و `push.secret` (رمز CI، مجوز ۶۰۰). رمز را در گفتگو، سند و لاگ نیاورید.

## نصب

```bash
mkdir -p ~/sur-registry && cd ~/sur-registry
# docker-compose.yml و nginx.conf را کنار هم بگذارید
umask 077
openssl rand -base64 36 | tr -d '/+=\n' | cut -c1-32 > push.secret
printf 'ci:%s\n' "$(openssl passwd -apr1 "$(cat push.secret)")" > htpasswd
chmod 644 htpasswd
docker compose up -d
WIPE=1 ./smoke-test.sh
```

برای IP دیگر: `SUR_REGISTRY_READ_BIND=<ip>:5000` و `SUR_REGISTRY_PUSH_BIND=<ip>:5001`.

## استفاده

- **CI (نوشتن):** `docker login <نشانی-در-نوشتن> -u ci --password-stdin`؛ `docker push <نشانی-در-نوشتن>/sur/<نام>@...`. ایمیج‌ها با هش منتشرشده ساخته می‌شوند.
- **ولیدیتور (خواندن):** `docker pull registry.surnet.org/sur/<نام>@sha256:<digest>`. همیشه با digest پین‌شده؛ برچسب (tag) به‌تنهایی کافی نیست.

## محدودیت‌ها

- `registry:2` تغییرناپذیری برچسب را اعمال نمی‌کند؛ برای همین ولیدیتور باید با digest بکشد.
- حذف ایمیج از رجیستری غیرفعال است (`REGISTRY_STORAGE_DELETE_ENABLED=false`)؛ پاک‌سازی با سیاست جدا و `garbage-collect` است.
- پشتیبان‌گیری از حجم `sur-registry-data` با مدیر سرور است.

## درخواست از مدیر سرور (✅ تصمیم مالک ۲۰۲۶-۱۱-۲۵: سرور نهایی را مدیر سرور تعیین می‌کند)

| # | درخواست | توضیح |
|---|---|---|
| ۱ | سروری داخل ایران با IP عمومی و دیسک کافی | ایمیج‌ها کوچک‌اند (NodeCheck حدود ۲۴۰ مگابایت، ایجنت حدود ۸ مگابایت، Besu چند صد مگابایت)؛ چند ده گیگابایت کافی است |
| ۲ | Docker و Docker Compose روی آن | کیت همین پوشه |
| ۳ | رکورد DNS برای `registry.surnet.org` | به IP عمومی همان سرور |
| ۴ | گواهی TLS برای این نام | certbot با تأیید HTTP؛ گواهی جدا، نه گواهی مشترک دیگر سرویس‌ها |
| ۵ | فقط در خواندن (۵۰۰۰) روی ۴۴۳ عمومی شود | در نوشتن (۵۰۰۱) فقط داخلی یا پشت VPN یا تونل ssh |
| ۶ | `htpasswd` و `push.secret` روی همان سرور ساخته شود | با دستور بخش «نصب»؛ رمز را در گفتگو و سند نیاورید |
| ۷ | پشتیبان‌گیری از حجم `sur-registry-data` و محدودیت نرخ در خواندن | |
| ۸ | آزمون: `smoke-test.sh` روی سرور و `docker pull` از یک شبکهٔ بیرونی | خبر آزمون به پروژه برگردد تا مستندات تکمیل شود |

## برای عمومی‌کردن (جزئیات)

1. سرور با IP عمومی داخل ایران؛ رکورد DNS `registry.surnet.org`.
2. گواهی TLS جدا برای این میزبان (certbot با تأیید HTTP)؛ در خواندن را روی ۴۴۳ منتشر کنید و **فقط** در خواندن را.
3. در نوشتن فقط داخلی یا پشت VPN بماند.
4. محدودیت نرخ برای در خواندن، و بررسی دسترسی از شبکهٔ ولیدیتورها.
