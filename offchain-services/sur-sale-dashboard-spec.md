# مشخصات فنی کامل — داشبورد عمومی فروش دوره‌ی قیمت ثابت

> این سند به‌تنهایی برای پیاده‌سازی کافی است. تمام داده‌ها مستقیم از توابع `view` و رویدادهای قرارداد `SurenSale.sol` گرفته می‌شوند — هیچ بک‌اند اختصاصی یا دیتابیس لازم نیست.

## ۱. نقش کلی

یک صفحه‌ی عمومی و ساده که روند فروش موجودی توسعه‌ی اکوسیستم بنیاد (بخش ردیف ۱ توزیع genesis — به `sur-tokenomics.md` مراجعه کن) را زنده نشان می‌دهد. مهم‌ترین سیگنال عمومی برای پیش‌بینی قیمت بازار آزاد پس از پایان دوره‌ی پگ.

## ۲. کاربر هدف

عموم — خریداران بالقوه، جامعه، و خودِ بنیاد برای پایش داخلی. بدون نیاز به اتصال کیف‌پول یا احراز هویت (فقط خواندن داده‌ی عمومی).

## ۳. معماری داده — کاملاً on-chain، بدون بک‌اند

قرارداد `SurenSale.sol` تمام داده‌ی لازم را مستقیم افشا می‌کند؛ این داشبورد فقط یک فرانت‌اند خالص است که این توابع را می‌خواند:

| تابع/رویداد قرارداد | داده |
|---|---|
| `getBalance()` | موجودی باقی‌مانده (به wei سورن) |
| `currentPriceToman()` | قیمت فعلی هر سورن، به تومان |
| `currentMonthIndex()` | کدام ماه از دوره‌ی ۶ماهه هستیم (۰ تا ۵) |
| `timeRemaining()` | ثانیه‌های باقی‌مانده تا پایان دوره‌ی فروش |
| `isSaleActive()` | آیا دوره هنوز فعال است |
| `totalSurenSold()` | مجموع سورن فروخته‌شده تا این لحظه |
| `totalTomanReceived()` | مجموع تومان دریافت‌شده تا این لحظه |
| رویداد `PaymentReported` | هر پرداخت — برای ساخت نمودار روند زمانی |

## ۴. پشته‌ی فنی

| لایه | انتخاب |
|---|---|
| فریم‌ورک | React (Next.js — با ISR یا SSR برای بارگذاری اولیه‌ی سریع، چون این صفحه عمومی و SEO برایش مهم است) |
| خواندن قرارداد | `viem` (بدون نیاز به `wagmi`، چون هیچ تراکنش امضاشونده‌ای در این صفحه وجود ندارد — فقط `readContract`) |
| نمودار | `recharts` |
| استایل | Tailwind CSS |
| زبان | فارسی |

## ۵. طرح صفحه (تک‌صفحه‌ای)

### ۵.۱ نوار وضعیت بالای صفحه
سه کارت کنار هم:
- **قیمت فعلی:** عدد بزرگ، `currentPriceToman()` تومان.
- **موجودی باقی‌مانده:** `getBalance()` (تبدیل‌شده از wei به سورن با ۱۸ رقم اعشار)، با یک نوار پیشرفت که نسبت `باقی‌مانده / (باقی‌مانده + totalSurenSold())` را نشان می‌دهد.
- **زمان باقی‌مانده:** `timeRemaining()` تبدیل‌شده به روز/ساعت خوانا؛ اگر `isSaleActive() === false`، به‌جایش نوشته شود «دوره‌ی فروش پایان یافته — قیمت از این پس در بازار آزاد تعیین می‌شود».

### ۵.۲ نمودار روند فروش
- محور افقی: زمان (بر اساس timestamp هر رویداد `PaymentReported`).
- محور عمودی: مجموع تجمعی سورن فروخته‌شده (جمع تجمعی `surenAmount` هر رویداد).
- خط دوم (اختیاری، رنگ متفاوت): پله‌های قیمت رسمی طبق `monthlyPriceToman` (۶ نقطه‌ی ثابت — این مقادیر مستقیم قابل‌خواندن از `monthlyPriceToman(uint256)` برای هر اندیس ۰ تا ۵ است).
- بازه‌ی داده: با `getLogs` روی رویداد `PaymentReported` از بلاک دیپلوی قرارداد تا الان (بلاک دیپلوی باید در پیکربندی فرانت‌اند هاردکد شود، برای جلوگیری از اسکن کل زنجیره از بلاک صفر).

### ۵.۳ جدول جدول‌بندی قیمت ۶ماهه (ثابت، بدون نیاز به فراخوانی زنجیره در هر بار — همان ۶ عدد `[100, 103, 106, 109, 113, 116]` طبق `sur-tokenomics.md`، فقط ماه فعلی با یک نشانگر بصری مشخص شود که کدام ردیف با `currentMonthIndex()` مطابقت دارد).

## ۶. تازه‌سازی داده

- کارت‌های بالای صفحه: هر ۳۰ ثانیه (`setInterval` ساده یا `refetchInterval` اگر از React Query هم استفاده شود).
- نمودار: هر ۵ دقیقه (چون نیازمند `getLogs` است که سنگین‌تر از `readContract` ساده است).

## ۷. مدیریت خطا

| خطا | رفتار |
|---|---|
| خطا در اتصال RPC | نمایش آخرین مقدار موفق ذخیره‌شده (cache) + یک نشانگر کوچک «داده ممکن است قدیمی باشد» |
| `getLogs` timeout (شبکه‌ی RPC عمومی محدودیت بازه دارد) | تقسیم بازه به بخش‌های کوچک‌تر (مثلاً هر ۱۰,۰۰۰ بلاک) و ادغام نتایج |

## ۸. امنیت

این صفحه هیچ تراکنش امضاشونده‌ای ندارد — سطح ریسک امنیتی‌اش تقریباً صفر (فقط خواندن داده‌ی عمومی). تنها نکته: آدرس قرارداد `SurenSale` باید از یک منبع پیکربندی‌شده و ثابت خوانده شود، نه از ورودی کاربر، تا کسی نتواند با یک لینک جعلی (query parameter) کاربر را به خواندن یه قرارداد جعلی هدایت کند.

## ۹. سؤالات باز

هیچ سؤال فنی باقی نمانده. فقط یک وابستگی عملیاتی: آدرس دیپلوی‌شده‌ی واقعی `SurenSale.sol` و شماره‌بلاک دیپلویش، بعد از دیپلوی واقعی قرارداد باید در پیکربندی این داشبورد قرار بگیرد.
