# Findings: unexpected or noteworthy results (Besu round 1, v2.5)

No contract bug was found and `contracts/` was not changed. Items for review:

- **F-1 (low, Besu behaviour).** Besu's QBFT contract-mode validator provider logged `IllegalStateException: Failed validator smart contract call: unable to execute call at block N` (in `TransactionValidatorProvider.getValidatorsFromContract`, surfaced as `EventMultiplexer ERROR State machine threw exception`). It occurred 8 times in about 1,100 blocks on multi-validator Net-A (n1 at blocks 320, 574, 581; n2b at 478, 566; n3b at 546; n5 at 372; n2 at 287) and never on the single-validator nets. Each time it coincided with a block import through `PersistBlockTask` in the same millisecond, so it is probably a race between block import and the BFT message handler asking for the validators after that block. Observed effect: one BFT message dropped each time, no block-time gap (gaps stayed 2 s). Evidence: `logs/Net-A/*.log`. Recommendation: check or file upstream before mainnet and monitor for it.
- **F-2 (info).** In contract mode the block header `extraData` validator list is empty. Tools that read validators from the header see none; use `qbft_getValidatorsByBlockNumber` or the contract.
- **F-3 (info).** The QBFT set reported at the block that contains a registry change already reflects the change, and no old operator mined in any later block checked (BG-03, 04, 06, 07). There was no isolated experiment of the exact proposer of block B+1.
- **F-4 (design observation, medium).** After a seat transfer `ownerOfOperator[op]` points to the buyer, so blocks mined by that operator BEFORE the transfer map to the buyer if the current mapping is used. BG-06 shows `ownerOfOperator(op7) == buyer`; BG-08a attributed blocks correctly (owner7 58 blocks, buyer 23) only because the script replayed `SeatTransferred` events. The Registry comment says an old operator key can always be mapped to its owner for reward purposes: that holds for `setOperator` swaps but not across seat transfers. The RewardRouter must use event history (or the contract needs a per-block-range owner record).
- **F-5 (info).** One validator node down costs a 12 s round change on that validator's turn (every 4th block at n=4, every 7th at n=7; `requesttimeoutseconds=10`). A `setOperator` to a node that is not running is accepted by the contract and silently degrades block time (BG-03 B).
- **F-6 (info).** After a halt below quorum and a restart (BG-13), recovery took 83 s and the first block came at round 3 (143 s since the last block). The contract-defined set was unchanged.
- **F-7 (info).** `eth_call` at head == target+250 evaluates `reveal` as still open, while a transaction mined one block later would be refused. The effective window for a transaction is "mined at block target+250 or earlier".
- **F-8 (info).** `--sync-min-peers` is ignored in FULL sync mode, and a 1-validator node logs "Waiting for 5 peers minimum" while producing blocks normally.
