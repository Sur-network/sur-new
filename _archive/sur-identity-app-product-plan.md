# سند محصول — اپلیکیشن احراز هویت عمومی

> فرانت‌اند قرارداد `IdentityRegistry` (ششمین قرارداد ساختاری). برای مشخصات فنی بک‌اند/API به `sur-identity-registry-spec.md` مراجعه کن؛ این سند فقط سطح محصول (چشم‌انداز، کاربر، ویژگی، UX) را پوشش می‌دهد — مشابه ساختار `sur-product-development-plan.md`.

---

## چشم‌انداز

رابط کاربری‌ای که **هر کاربر شبکه‌ی سور** (نه فقط ولیدیتورها) با آن هویتش را ثبت، موبایل/تلگرامش را وریفای، و در صورت نیاز eKYC کامل را تکمیل می‌کند.

## کاربر هدف — چرا این با اپ Verifier فرق دارد

| | اپ Verifier (قبلاً ساخته شد) | این اپ (تازه) |
|---|---|---|
| کاربر | فقط ولیدیتورها | **کل کاربران شبکه** |
| داده‌ی جمع‌آوری‌شده | موبایل، تلگرام، `nodeID` | موبایل، تلگرام، + (اختیاری) عکس/کارت‌ملی برای KYC |
| حساسیت داده | متوسط | بالا (برای مسیر KYC) |
| هدف نهایی | اثبات وجود یک نود سالم | اثبات هویت واقعی برای دپ‌ها/گرنت‌ها |

## ویژگی‌های اصلی (مستقیم از API سرویس Identity، بخش ۳ سند فنی)

1. **ورود با امضای اتریومی** — بدون رمز عبور، دقیقاً مثل اپ Verifier.
2. **ثبت‌نام پایه:** نام، نوع شخصیت (حقیقی/حقوقی) → تراکنش مستقیم `registerIdentity`.
3. **وریفای موبایل/تلگرام:** جریان OTP — دقیقاً همان الگوی اپ Verifier.
4. **مسیر eKYC (اختیاری، برای کاربرانی که نیازش دارند):**
   - آپلود سلفی + عکس کارت ملی.
   - هدایت به سرویس‌دهنده‌ی eKYC مجاز (تطبیق چهره + liveness detection).
   - نمایش وضعیت («در حال بررسی» / «تأیید شد» / «رد شد»).
5. **صفحه‌ی وضعیت:** نمایش هرسه فلگ (موبایل/تلگرام/KYC) — دقیقاً `getVerificationStatus`.
6. **جریان مهاجرت کلید:** اگر کاربر کلیدش را گم کرد، فرآیند اثبات مالکیت مجدد (🔶 جزئیات دقیق هنوز در سند فنی باز مانده، بخش ۳.۴).

## ملاحظات UX

- زبان فارسی، مطابق کاربر هدف.
- **شفافیت درباره‌ی داده‌ی حساس:** قبل از شروع مسیر eKYC، باید صریح توضیح داده شود این تصاویر پیش چه سرویس‌دهنده‌ای می‌رود و چقدر نگه‌داری می‌شود (طبق سیاست نگه‌داری سند فنی).
- **جداسازی بصری واضح بین ثبت‌نام پایه و KYC کامل** — کاربری که فقط می‌خواهد ولیدیتور شود، نباید فکر کند مجبور به آپلود کارت ملی است.

## اولویت و وابستگی

🟡 مهم، نه فوری‌ترین — قرارداد `IdentityRegistry` بدون این اپ هم می‌تواند مستقیماً (با ابزار خام) صدا زده شود برای ثبت‌نام پایه، ولی مسیر eKYC عملاً بدون یک رابط کاربری واقعی غیرقابل‌استفاده است.

**وابستگی:** API بک‌اند سرویس Identity (`sur-identity-registry-spec.md`، بخش ۳) باید از قبل مشخص باشد؛ انتخاب سرویس‌دهنده‌ی eKYC (سؤال باز #۱ همان سند) مستقیم روی طراحی قدم ۴ اثر می‌گذارد.
